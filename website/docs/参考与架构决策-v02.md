## 设计与体验

用户选择 G / H，要求减少 App 的占比，参考 UI、UX、前后端、架构与动效。采用的主线是个人介绍、网站与业务工具、客户参与经历。App 留在独立实验页，不作为首页形象。

模板仅作视觉与交互研究，没有下载或复用商业模板资产。许可不能从“可浏览”推断。本轮不购买模板。

执行了 ui-ux-pro-max 的 design-system 与 UX 查询。保留触控尺寸、可见焦点、当前位置提示、URL 状态、减少动态等建议；舍弃自动推荐的蓝色、手写英文字体和多层视差，以用户已选 G/H、中文内容和实际素材为准。Finesse 的静态纹理、字体层级和反廉价检查用于细化版面；ask-matt 用于确定本轮沿已有原型继续实现和复核的流程，没有另建任务或安装追踪器。

## 架构对照

对照 3 个官方方案及现有实现。这里比较功能与维护成本，没有安装候选框架或声称完成依赖安全审计。

| 候选与原始文档 | 许可证与维护入口 | 适合点 | 本轮决定 |
| --- | --- | --- | --- |
| [Astro](https://docs.astro.build/en/concepts/why-astro/) | [官方仓库 / MIT / Security](https://github.com/withastro/astro) | 内容驱动，默认静态 HTML，交互按需加入，内容集合可校验 | 借用内容先渲染、交互独立的原则；未来文章/CMS 增长时优先重新评估 |
| [Eleventy 文档](https://www.11ty.dev/docs/) | [官方仓库 / MIT / Security](https://github.com/11ty/buildawesome) | 模板与数据分开，适合静态个人网站 | 借用模板/数据分离。本次旧仓库入口跳转 Build Awesome，若采用需核实对应版本与迁移说明 |
| [Next.js Server/Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components) | [官方仓库 / MIT / Security](https://github.com/vercel/next.js) | 同一项目覆盖服务端与浏览器交互，适合账户和动态业务 | 当前没有账户、个人化数据或事务，暂不承担相应运行与依赖成本 |
| 当前标准库静态构建 | 自有代码，Python 标准库；没有新增第三方构建依赖 | 本地已可运行，输出直接 HTML，迁移与托管简单 | 保留；把原先混在一个文件中的构建、内容校验、组件与页面分开 |

## 当前实现

`content/*.json → scripts/content.py 校验 → scripts/pages.py 组装 → templates/*.html / scripts/components.py → dist/`。

- 内容：38 条记录保持原始阶段，不把参与、原型与商业交付混为一谈。重复 ID、缺字段、非法路由 ID、缺图片在写输出前拒绝。
- 模板：布局、项目卡片、记录行与页面各自可编辑。资料字符串统一 HTML 转义；图片使用真实宽高，减少布局变化。
- 浏览器：`app.js` 只负责位置提示、分类与搜索。筛选/查询写入 URL，刷新与返回可以恢复；空结果可一键重置。
- 无 JavaScript：正文、案例、导航和原生 details 展开仍可用；不可用的搜索工具不会假装能操作。
- 本地预览服务只提供 `dist/`，绑定 127.0.0.1；原始资料、内部文档、内容 JSON 和构建脚本不会由服务公开。

## 后端参考与接入条件

[Astro 按需渲染文档](https://docs.astro.build/en/guides/on-demand-rendering/) 说明静态页面可以与需要服务端的路由分开。Next.js 的服务端/客户端边界提供另一种全栈方案。对本站的判断是：个人介绍、图片和 38 条本地搜索无需请求业务 API；Python 预览服务不属于生产后端。

若后续确定联系表单，先明确收件目标、字段和保存期限，再实现独立提交端点、服务端校验、请求限制、真实成功/失败反馈。若需要在线改内容，再比较 CMS/内容集合与权限模型。当前没有这两项需求，不建数据库、账户或虚假提交接口。后台与生产部署另按具体授权实施。

## 动效的用途与边界

- 按压轻微缩放：确认点击；180ms。没有 JS 依赖。
- 案例图片悬停：提示可打开案例；240ms，小幅缩放，触屏不依赖 hover。
- 链接箭头：指明导航方向；180ms。
- 导航项：标记当前读到的区块，不拦截滚动。
- 页面过渡：180ms 交叉淡入，维持浏览连续性；原生导航和焦点顺序保留。`prefers-reduced-motion: reduce` 关闭过渡与运动。

没有宣称实机 60fps、跨浏览器全覆盖或线上 Core Web Vitals 通过。当前证据是本机浏览器模拟视口和减少动态偏好检查。
