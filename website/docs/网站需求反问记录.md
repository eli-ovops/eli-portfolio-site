# 网站需求反问记录

> 适用阶段：P0 机会判断与范围控制。
> 使用原则：先反问、后立项。未知信息统一写“待确认”；AI 只能整理原始回答和提出建议，不能把建议补成项目事实，也不能代填确认人或确认日期。

## 1. 状态与编号规则

- 需求编号使用 `REQ-P0-NNN`，编号一经引用不得重排。
- 条目状态只能使用：`待填写 / 待确认 / 已确认 / 不适用 / 阻塞`。
- 阶段门禁结论只能使用：`通过 / 条件通过 / 退回`。
- 正常流转为：`待填写 -> 待确认 -> 已确认`；需求变化后退回 `待确认`。
- `不适用` 必须写明理由，并由具名人工确认人确认。
- AI 生成内容只能进入“AI 整理或建议”栏，条目状态保持 `待确认`。

### 通过标准

- 项目定位、目标用户、核心动作、转化路径、页面、功能、角色、数据、内容、素材、环境、上线级别、不做范围和验收标准均有明确状态。
- 关键事实有来源或具名人工确认人；未知项保留“待确认”。
- 预算和周期只记录已确认状态，不把示例时长或 AI 推测写成承诺。

### 退回或降级条件

- 任何阻塞项被 AI 补写为事实、缺少确认人，或目标、范围、上线级别无法判断时，退回补问。
- 数据或隐私责任未确认时，不得使用真实数据。
- 关键项未确认时，只能进入 P1 调研、P2 草案或 L0 Demo；不得声称正式立项、L1/L2 完成或生产可用。

## 本任务填写快照（当前用户任务优先）

原始要求：实际完成通用个人网站及本地预览，自主选择首版设计，不先要求整理或设计批准。

REQ-P0-001 定位/目标：个人介绍、性格、能力、作品、可核实成果；本地首版已授权。REQ-P0-002 用户：未来招聘方或潜在客户；具体优先次序待确认。REQ-P0-003 动作/转化：作品→详情→个人介绍；联系方式缺失则隐藏。
