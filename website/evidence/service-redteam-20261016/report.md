# 线上三个服务页对抗审查 · 2026-10-16

审查对象：https://www.eliai.cn/services/fde-consulting.html、ai-agent.html、workflow-automation.html。实测线上 revision 为03985a2ddb6824f06f7f。

结论：三个页面可阅读、案例能进入、咨询可以完成跳转；服务定位仍偏“先评估”，对搜索进站的老板，具体能得到什么和为什么找你还不够突出。保留现有视觉和动效即可，无需换模板。

## 优先问题

### P1 服务表述仍偏咨询过程，具体交付不够突出

三个首屏都强调先梳理、评估工具和试一个场景，降低了起步门槛，这是有效信息。但老板仍需从较长正文归纳：你帮我配置工具、连接资料、改造流程，还是负责开发和交接？这属于审查者的转化判断，不是客户访谈结果。

建议每页各用一条短摘要说明“我的问题→你帮我做的事→可以约定的交付”，后续范围在咨询时确认。不要编造固定交付周期、收益或免费咨询成果。FDE突出业务梳理和实施；Agent突出知识检索/答疑及需要另行验证的执行动作；企业提效突出录入、库存与内容准备。

### P2 案例证据偏后，标题层级偏弱

390×844模拟视口，案例区文档位置：FDE2048px、Agent2137px、企业提效2099px，约第三屏附近。案例链接计算字号14px，正文16px；命中高度44px，故不是因为触控目标太矮，而是证据视觉权重弱。移动目录可横滑，视口337px、内容1017–1320px，案例入口位于较后项。

建议首屏保留咨询入口，再给一个轻量“看相关案例”锚点或一条短案例证据；案例标题至少与正文平级。无需增加大卡片或首屏长文。

### P2 返回去向在服务路径中不连续

实测“企业提效服务页→P10→案例页内返回项目库”确实进入records.html。该按钮文字与去向一致，不能算错链；但它没有返回刚才服务页的能力。浏览器Back可回服务页#cases附近，本轮约scrollY1909。因此应区分网站入口连续性缺口与浏览器返回故障。

建议返回来源管理支持服务页，保留服务路径和锚点；从项目库进入时继续维持原搜索筛选来源。相关案例串行浏览也应继承同一来源，别一律改成history.back。

### P2 Agent搜索意图比现有证明范围宽

页面清楚区分知识问答与执行动作，边界表达正确；但唯一相关案例是P36知识库整理、检索配置与测试，不能把它当成已经交付任意业务执行Agent的证据。

建议首屏明确已有经验覆盖的知识检索/答疑，并单列需要评估的工具调用场景；如后续有真实执行链记录，再补过程证据。保留问答示意与真实记录的区分。

### P3 联系可达，但缺少开口辅助

三页咨询链接均到about.html#contact，FDE和Agent在320px、企业提效在390px均实点到达且联系区在可见范围。邮箱、电话、WhatsApp及微信二维码链接存在；未发邮件、拨号或测试外部消息送达。共享联系页没有带入服务主题，中文微信只见二维码，无可见微信号复制入口。

建议给一句可复制的咨询开场模板，或者在同一联系入口显示来源服务。不要虚构微信号或承诺响应时限。
